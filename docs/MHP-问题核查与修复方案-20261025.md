## 新增确认：模板保存字段不兼容

优先级 P1，当前功能阻断。

- 前端 `frontend/src/views/PTMDWorkbench.vue:75` 将完整 setSpec 作为模板 payload.spec 保存。
- `frontend/src/ptmdDraft.js:11` 总会包含 text_rendering；第25/27行总会包含 title_zh / copy_lines_zh。
- 后端 `app/api/workspace.py:76` 的 spec 白名单没有 text_rendering；第90行的页面白名单没有 title_zh / copy_lines_zh。
- 直接调用当前 Template 校验：带 text_rendering 的草稿被拒绝；删除该字段后，含中文翻译字段的页面仍被拒绝。此复现无需访问数据库或调用模型。
- 7个现有内置预设本身均通过当前模板校验，因其仍使用旧字段集合；这不能证明新草稿可保存。

修复方案：模板 schema 与当前 ProductSetSpec / SetPage 对齐，明确接受并校验上述字段，保留严格类型、长度、禁止未知字段和清除私有素材ID的约束；兼容旧模板缺省值。不要通过删除翻译或排字选择来绕过校验。

验收：新草稿、AI双语方案分别保存→导出→导入→套用；字段保持一致，原图及参考图ID清空；旧版模板仍可套用；非法未知字段和跨账号素材引用仍被阻止。流程无需真实生图。

## 签到及注册补充判断

`app/services/credit_service.py:19` 用服务端 Unix 时间换算北京时间日期；第50行起在事务内写入奖励。`app/models/billing_schema.py:9` 提供唯一约束。

本轮用临时 SQLite、合成账号及固定时钟验证：

| 场景 | 实际结果 |
| --- | --- |
| 同账号连续5次签到 | awarded = 2, 0, 0, 0, 0 |
| 同账号24请求、12线程并发 | 仅1次 awarded=2，其余0；累计2，签到记录1条 |
| 次日签到 | awarded=2 |
| 北京时间午夜边界 | UTC 15:59:59 仍当天；UTC 16:00:00 为次日 |

这些结果不能替代正式库约束检查，也没有模拟部署多个独立数据库的情形。

注册验证码已有邮箱冷却、邮箱每小时次数、来源IP每小时次数和全站每日次数限制（auth_service.py:187起）。未见设备维度额度规则。需确认反向代理传递的真实客户端IP；不要将数据库唯一防重与多账号注册风控混为一项，也不要无依据直接封禁共享IP。
